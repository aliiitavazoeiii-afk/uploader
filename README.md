# VideoDrop — سایت شخصی آپلود و دانلود ویدئو

پنل آپلود رمزدار، لینک دانلود مستقیم برای هر ویدئو، دانلود قابل‌ادامه و نمایش فضای دیسک. برای یک سرور Ubuntu/Debian با آدرس `45.142.189.66`.

## نصب یک‌مرحله‌ای روی سرور جدید

با کاربر root و روی خود سرور:

```bash
curl -fsSL https://raw.githubusercontent.com/aliiitavazoeiii-afk/uploader/main/scripts/bootstrap-new-server.sh -o /root/videodrop-setup.sh && bash /root/videodrop-setup.sh
```

اسکریپت، وابستگی‌های پایه و در صورت نیاز Docker Engine + Compose را نصب می‌کند؛ قبل از استقرار از آزاد بودن پورت‌های TCP 80/443 اطمینان می‌گیرد؛ پیکربندی Caddy را اعتبارسنجی می‌کند؛ سایت را راه‌اندازی و آزمایش می‌کند.

آدرس سایت بعد از نصب موفق و صدور گواهی HTTPS:

https://45-142-189-66.sslip.io

رمز مدیریت فقط هنگام ایجاد اولیه در ترمینال نمایش داده می‌شود و در `/opt/video-share/.env` ذخیره می‌شود. این فایل محرمانه است و نباید در اختیار دیگران قرار گیرد.

## آپدیت بدون حذف داده‌ها

روی همان سرور اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/aliiitavazoeiii-afk/uploader/main/install.sh -o /root/video-share-install.sh && bash /root/video-share-install.sh
```

ویدئوهای کامل داخل `/opt/video-share/data/videos`، فهرست داخل `/opt/video-share/data/index.json` و اطلاعات ورود در `/opt/video-share/.env` ذخیره می‌شوند. اسکریپت آپدیت آن‌ها را پاک نمی‌کند.

## مشاهده وضعیت

```bash
cd /opt/video-share
docker compose ps
docker compose logs --tail=80 app web
```

سایت از آپلود **مستقیم** (یک درخواست پیوسته، بدون آپلود چندبخشی) استفاده می‌کند. سقف فایل به فضای آزاد دیسک و محدودیت ۳۰ GiB داخل برنامه بستگی دارد؛ حداقل ۱.۵ GiB برای سیستم محفوظ می‌ماند. آپلود نیمه‌کاره Resume نمی‌شود و با قطع ارتباط باید از ابتدا شروع شود؛ دانلود HTTP Range قابل‌ادامه است. انتقال فایل‌های چندگیگابایتی همچنین به پهنای باند و پایداری مسیر اینترنت بستگی دارد.

Caddy روی HTTP/1.1 و HTTP/2 و مهلت بی‌حرکتی آپلود ۱۰ دقیقه تنظیم شده است. TCP 80 و 443 باید در فایروال سرور و پنل ارائه‌دهنده قابل دسترسی باشند.

**توجه:** فایل‌های سرور قبلی `185.190.53.142` به سرور جدید خودکار انتقال داده نمی‌شوند. هر کسی لینک اختصاصی ویدئو را داشته باشد می‌تواند فایل را دریافت کند.


## نصب کنار فروشگاه دارما روی همان سرور 45.142.189.66

**پورت‌های 80 و 443 متعلق به کانتینر darmawear-store-caddy هستند.** اسکریپت نصب عادی پروژه نباید روی این سرور اجرا شود. به جای آن:

```bash
curl -fsSL https://raw.githubusercontent.com/aliiitavazoeiii-afk/uploader/main/scripts/install-alongside-darmawear.sh -o /root/videodrop-alongside.sh && bash /root/videodrop-alongside.sh
```

این نصب:
- خود اپ را در کانتینر videodrop-uploader و پوشه /opt/videodrop-sidecar راه‌اندازی می‌کند
- پورت 8789 را فقط روی 127.0.0.1 باز می‌کند
- اپ را به شبکه Docker مشترک با Caddy فروشگاه متصل می‌کند
- Caddyfile ذخیره‌شده روی هاست را پیدا، بکاپ و پیکربندی افزوده‌شده را validate می‌کند
- یک route مجزا به 45-142-189-66.sslip.io اضافه می‌کند و Caddy موجود را با reload بدون stop/recreate کردن فروشگاه بروزرسانی می‌کند
- در نبود Caddyfile پایدار/قابل ویرایش، روی پورت اشغال یا پیکربندی غیرقابل اعتبارسنجی، متوقف می‌شود

کاربر باید در صورت اشتراک خروجی نصب، خط ADMIN_PASSWORD را سانسور کند. فایل‌های فروشگاه دست‌نخورده می‌مانند؛ پیکربندی Caddy مشترک تغییر محدودی خواهد داشت و فایل پشتیبان آن چاپ می‌شود. 5 GiB فضای آزاد برای محافظت از فروشگاه رزرو می‌شود.

این نصب به‌طور خودکار فایل‌های ویدئویی سرور قبلی را منتقل نمی‌کند.
