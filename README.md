# VideoDrop — شخصی برای اشتراک‌گذاری ویدئو

وب‌سایت سبک فارسی برای آپلود ویدئو روی سرور شخصی و دادن لینک دانلود مستقیم.

- پنل مدیریت با رمز تصادفی
- لینک عمومی با شناسه تصادفی مجزا برای هر فایل
- آپلود با نمایش پیشرفت
- دانلود با قابلیت ادامه (HTTP Range)
- حذف ویدئوها از پنل
- نمایش میزان فضای آزاد دیسک
- نگهداری حداقل ۱.۵ گیگابایت فضای خالی
- HTTPS خودکار با Caddy

## نصب مستقیم از GitHub روی Ubuntu / Debian

سرور: `185.190.53.142`

نیازمندی‌ها: Docker Engine، افزونه Docker Compose، openssl و curl. پورت‌های TCP 80 و 443 باید آزاد باشند و از اینترنت قابل دسترسی باشند.

در ترمینال سرور با root اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/aliiitavazoeiii-afk/uploader/main/install.sh -o /root/video-share-install.sh && bash /root/video-share-install.sh
```

آدرس بعد از نصب موفق و دریافت گواهی HTTPS:

https://185-190-53-142.sslip.io

رمز مدیریت در اولین نصب روی ترمینال نمایش داده می‌شود و در `/opt/video-share/.env` ذخیره می‌گردد.

## وضعیت و لاگ

```bash
cd /opt/video-share && docker compose ps && docker compose logs --tail=50
```

داده‌ها در `/opt/video-share/data` نگهداری می‌شوند. فایل ویدئو در `data/videos` و فهرست در `data/index.json` است. حذف ویدئو از سایت فایل را نیز حذف می‌کند. با حذف کانتینر فایل‌ها از بین نمی‌روند؛ اما حذف پوشه `data` باعث از دست رفتن اطلاعات می‌شود.

## نکات مهم

نصب‌کننده تلاش نمی‌کند سرویس‌های دیگر سرور را متوقف کند. در صورت اشغال بودن ۸۰ یا ۴۴۳، نصب متوقف می‌شود و باید سایت را به reverse proxy موجود متصل کنید.

رمز فقط برای مدیر لازم است؛ **هر کسی لینک یک فایل را داشته باشد می‌تواند آن را دانلود و بازنشر کند**. فایل‌های خصوصی را فقط با افراد مورداعتماد به اشتراک بگذارید.

اگر Docker یا Compose موجود نیست، مطابق مستندات رسمی Docker نصب کنید: https://docs.docker.com/engine/install/

برای اجرای مستقیم از سورس بدون آرشیو تعبیه‌شده، پس از clone کردن مخزن اسکریپت `scripts/install-from-source.sh` نیز وجود دارد. 


## به‌روزرسانی نسخه سریع (بدون حذف فایل‌ها)

در سرور با کاربر root اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/aliiitavazoeiii-afk/uploader/main/install.sh -o /root/video-share-install.sh && bash /root/video-share-install.sh
```

این دستور نسخه جدید را از GitHub دانلود می‌کند، از کد قبلی نسخه پشتیبان می‌گیرد و فقط کانتینرهای VideoDrop را بازسازی می‌کند. فایل‌های ویدئو در `/opt/video-share/data` و رمز ورود در `/opt/video-share/.env` حفظ می‌شوند.

**بهبودها:** آپلود چندبخشی با ۴ درخواست هم‌زمان و تلاش مجدد خودکار برای بخش‌های ناموفق، نمایش سرعت به Mbps، و پشتیبانی اختیاری HTTP/3 از طریق UDP پورت 443. این ویژگی‌ها برای مسیرهای نامطمئن مفیدند اما افزایش سرعت را در همه مسیرها تضمین نمی‌کنند.

برای فعال‌شدن HTTP/3 در صورت فعال بودن فایروال، UDP پورت 443 نیز باید مجاز باشد؛ HTTP/2 و HTTPS بدون این پورت همچنان کار می‌کنند. آپلودهای در حال انجام را پیش از به‌روزرسانی تمام کنید. بعد از نصب، صفحه را یک بار با Ctrl+F5 باز کنید.

**عیب‌یابی سرعت:** اگر سرعت پایین بود، سرعت اینترنت آپلود دستگاه، مسیر شبکه به IP سرور و کارکرد دیسک را بررسی کنید. این سایت محدودکننده نرم‌افزاری سرعت ندارد.


## رفع توقف ظاهری آپلودهای بزرگ (نسخه ۲)

- پیشرفت با دو رقم اعشار و مقدار مگابایت ارسال‌شده نمایش داده می‌شود. عدد Mbps سرعت متوسط ارسال گزارش‌شده توسط مرورگر است، نه اثبات ذخیره کامل فایل روی سرور.
- ارسال چندبخشی با سه اتصال هم‌زمان و تلاش مجدد پس از ۹۰ ثانیه توقف هر بخش انجام می‌شود.
- HTTP/3 برای رفع اختلال احتمالی UDP موقتاً غیرفعال شده و سایت از HTTP/1.1 یا HTTP/2 استفاده می‌کند.
- پس از به‌روزرسانی فایل‌های تکمیل‌شده و رمز مدیریت باقی می‌مانند؛ آپلود ناقص هنگام راه‌اندازی دوباره از ابتدا شروع خواهد شد.
- اگر همچنان مشکلی بود: `cd /opt/video-share && docker compose logs --tail=80 app web`

## رفع خطای 502 پس از 60 ثانیه هنگام آپلود از اینترنت

لاگ‌های واقعی نشان دادند آپلود مستقیم به Node و آپلود HTTPS روی خود سرور موفق است، اما در آپلود از شبکه کاربر Caddy پس از حدود ۶۰ ثانیه خطای `readfrom ... i/o timeout` ثبت می‌کرد. این زمان با `read_body_idle` پیش‌فرض Caddy تطابق دارد. برای مسیرهای کند، `read_body_idle 5m` تنظیم و پروتکل سمت مرورگر به HTTP/1.1 محدود شد؛ فایل به قطعات ۵۱۲ کیلوبایتی و یک اتصال هم‌زمان ارسال می‌شود.

این تنظیمات **سرعت واقعی خط اینترنت را افزایش نمی‌دهند** و اگر مسیر اینترنت/VPN مسدود یا به شدت کند باشد، لازم است آن مسیر هم بررسی شود. برای تشخیص مسیر پس از نصب، با فایل ویدئویی کوتاه تست کنید و در صورت تکرار خطا، این دستور را اجرا کنید:

```bash
cd /opt/video-share && docker compose logs --since=10m --tail=100 app web
```

اسکریپت نصب پیش از ری‌استارت سرویس‌ها، پیکربندی Caddy را اعتبارسنجی می‌کند؛ رمز و فایل‌های کامل قبلی تغییر نمی‌کنند.
